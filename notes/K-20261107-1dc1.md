Found while checking the world map tool by driving the real app (2026-11-06).

- No API selects a tool: `api.world.submit({kind:'world/requestTool',...})` gets the world's answer but the client does not switch, only `worldClient.requestTool` does. To exercise a tool end to end, a script must click its palette tile.
- Headless Edge gives no pointer lock (`document.pointerLockElement` stays null). desktopControls only moves the palette cursor and takes clicks under the lock.
- Stub in the page: `Object.defineProperty(document,'pointerLockElement',{get:()=>canvas,configurable:true}); canvas.requestPointerLock=()=>Promise.resolve(); document.exitPointerLock=()=>{}`. Then right click opens the palette, `mouseMoved` steps give movementX/Y to the cursor, left click picks.
- The cursor moves in panel units per pixel, so the same deltas reach a tile at any viewport size: from the center, (-270,-32) reaches the fifth tile (second row, first column).
- `session.navigate` against `vite` dev times out at 6 s because the first document takes about that long; catching it is safe, the page still loads. Against the built site it is fine.
- Worlds with many faces (icosahedron) intermittently time out CDP commands at 1280x800 under SwiftShader; 640x400 is reliable.
- In this shell wrapper `node -e` with a multi-line script silently did nothing once; write a file instead.
