Reproduced at 95248d8 in the built app: Promise.all of two api.app.changeWorld calls, three world pairs; no namespace came back in up to 400 polls, so no slow older run is needed. Fixed in 9181a41. Scenario: tests/app/moduleApi.release.test.ts, 'keeps the live app's namespaces through two overlapping world changes'. setApiNamespace is by name with no owner, so nothing may install namespaces for a superseded run. The check sits inside the loadingStatus.track task, because track awaits a paint before the task; if createThreeApp ever becomes async the window reopens.
