Observed: cellRenderArchetypes.ts contains hasAncestorNamed(object, prefix), which walks parents and matches object.name prefixes such as "portal-debug-panel:" and "portal-debug-label:". A grep for static-object and decoration showed these name checks are used in the same file. When static asset roots were restructured, the agent edited this file and its tests (cellRenderArchetypes.test.ts, portalInstanceBuffers.test.ts) in the same change, which suggests the name matching was affected.

Concluded: this classification depends on Three.js object names, not on a typed marker. Renaming or re-parenting render roots can change clipping and debug classification without a type error. Check the name-prefix matches and their tests whenever render root names or hierarchy change.
