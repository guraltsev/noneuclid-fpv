Observed:
- Anchor-based doc insertion reported "ANCHOR PROBLEM" for several declarations in src/render/three (for example renderState.ts RuntimeInputFrame fields and cellRenderArchetypes.ts BuildCellRenderArchetypesOptions), while other anchors resolved.
- A CR-count check on the directory showed portalClipData.ts and renderState.ts contain 0 CR characters.
- git printed warnings that LF will be replaced by CRLF the next time Git touches portalClipData.ts, portalClipMaterial.ts and renderPortalInstances.ts.
- The agent re-ran edits with Python using open(..., newline='') and then re-checked anchors, and the subsequent checks passed (TSC OK, diffcheck done).

Concluded (hypothesis):
- The working copy has inconsistent line endings across files. Anchor or multi-line matching that assumes one ending can miss matches, so before scripted edits, check the file's line endings and read and write with newline='' (or normalize).
