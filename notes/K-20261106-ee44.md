Module leaker requires provider; publicApi go: () => provider.addThing() wrote provider/thing with no throw, because wrapApi pushes the provider's writable frame above the read-only one and assertMayWrite (writeGuard.ts:32-41) looks at the top only. A publicApi go: async () => { await null; objects.add(...) } also wrote with no throw: the frame was popped when the function returned its promise (writeGuard.ts:83-88). No module in the default experience does either today; the shipped wrappers only call submit, which queues. The same holds for queries frames by the same mechanism (not separately run). tests/modules/modulePublicApi.test.ts covers only the direct synchronous write.
