## Observed
- After editing several `_issues/*.md` files with Python scripts (steps 98, 104, 108, 112, 116, 122, 126, 138, 144), `git diff --stat` and later `git diff` output included many `warning: in the working copy of '_issues/...md', LF will be replaced by CRLF the next time Git touches it` lines (steps 101, 145).
- Step 101 ran `git ls-files --eol` on one issue file; the output was truncated but began with `i/lf`.
- The diff stat at step 145 listed the edited issue files with line counts in the tens, consistent with the edits themselves.

## Concluded
- The repository index stores these issue files with LF line endings, while the Windows working copy has a line-ending setting that git wants to convert on touch. Scripted edits should preserve the existing line endings, and diff-size checks should be read with this warning in mind.

## Not verified
- The exact git autocrlf or .gitattributes configuration was not inspected in the digest.
