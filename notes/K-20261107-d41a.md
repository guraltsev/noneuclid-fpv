World map (design 015). Each face lifts what stands on it along its own normal, and two lifted lines meet over an edge only if the geodesic crosses it square on, so at any height a ray is straight OR connected. Tried and failed: rays at beam height (gaps at edges); rays flat with tall emitters (ray detached from emitter); mitering ends to P + h(nA+nB)/(1+nA.nB) (connected, but visibly kinked on every face at h = 1.08 m). Resolved by giving nothing on the map any height.

How things are shown (maintainer decision, 2026-11-07): each object is a stylised road-map-style icon, `map-icon.svg` in the folder of its model, declared next to the model path (`mapIconPath` in library entries, carried through spec and runtime record; `placedFlagMapIconPaths`; `geodesicMapIconPaths`; the avatar definition) and preloaded with the models (.svg loads as a texture). All icons share one size as a fraction of the solid circumradius; the player's is larger. The earlier design, sprites rendered at run time from the real meshes in a three-quarter view at true scale, was rejected by the maintainer: they wanted icons stored with the objects and stylised (stop sign without pole). Evidence: headless screenshots of cube, tetrahedron, dodecahedron, icosahedron with icons, 2026-11-07. Not verified on a headset.

Probing tips: the map opens only through the palette's mouse flow (`api.world.submit` of requestTool does not select the client tool), so for screenshots patch the built bundle in dist (`selectedTool:"none"` -> `"worldMap/map"`) and rebuild afterwards. Never put a probe patch in src/: it reaches the user's running vite dev server.
