The write guard already ran an owner's `api` in the owner's frame (`wrapApi` -> `runFunctionsInFrame`), so no guard change was needed: carry tick -> emitters api (frame geodesicEmitters) -> model api (frame geodesicModel). Evidence: full suite with guard on, job 64.

- `shootGeodesic`, `rebuildGeodesicToLength`, `extendGeodesic`, `rebuildEmitterGeodesics` no longer write the emitter: a caller that changes the yaw stores the emitter itself. A test that expects a stored yaw after `shootGeodesic` with a candidate cannon gets none.
- `moveEmitterAlongRoute` takes `followRoute`; placements take `cuts`. Model commands (module-only): shootArc, extendArc, cutAtSegment, cutAtVertex, removePlainArcs. Model api, fast channel: retraceArc, followAnchorRoute, rebuildArcsOfEmitter.
- `carryModule()` now requires the emitters, which require the model: a test engine needs all three.
- `removeGeodesicIntervalAndDerivedObjects` leaves lengths and angles to the measurement ticks; on a bare registry they stay until a derive pass.
- `rebuildEmitterGeodesics` with a following arc rebuilds only following arcs: a plain arc on the same emitter is not regrown and stays behind (read and seen in a test, predates job 64).
