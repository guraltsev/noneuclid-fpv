Observed 2026-11-04 on this machine, while editing job files in the batch worktree.

- `.agents/jobs/52_...md` and `.agents/jobs/README.md` are CRLF (README also has a BOM); `_done/50_...md` is LF. A scripted replacement with `\n` in the search text silently fails to match the CRLF files. Normalise the search text to the file's line ending, or use `chr(13)+chr(10)`.
- A Python script passed through a heredoc in the Bash tool came out with `\\n` turned into real newlines and `\"` stripped, even with a quoted heredoc delimiter. Writing the script with the Write tool and running the file works. Exact cause not established.
- `_scripts/know_session_job` from Git Bash fails: it looks for `.agents/.state/knowledge/venv/bin/python`, which does not exist on this Windows venv. Run `_scripts\know_session_job.cmd` from PowerShell instead.
- Removing a scratch tree that has a `node_modules` junction: delete the junction first with `(Get-Item path).Delete()` so nothing recurses into the real folder.
