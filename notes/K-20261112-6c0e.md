Found 2026-11-12 while walking through ?config=001 and 005 on the built site (npm run server -- --http --dev).

- CDP `Input.dispatchMouseEvent` mouseMoved: the browser computes movementX/Y from position differences; steps coalesce and any click sent at a different x/y causes a jump, so the palette cursor lands in the wrong place.
- Page-dispatched `MouseEvent('mousemove', {movementX, movementY})` on the canvas is read by desktopControls exactly. Measured scale on a 1250x705 viewport: about 0.84 screen px of palette cursor per unit of movement.
- Clicks: dispatch mousedown/mouseup (button 0 left, 2 right) on the canvas. Right click with a menu closed opens the menu for the aim; F opens the focused object's menu too.
- `noneuclid.api.motion.run([{to: id, stopAt: 2.5, lookAt: id}])` stands you in front of an object, but thin objects (posts) may still not be focused; nudge pitch.
- Windows: `node` may be a .cmd shim, so arguments containing `>` are taken as cmd redirections (error 'Access is denied'). Pass page expressions through files.
- There is no API to open menus or select tools; tool state is visible in `noneuclid.api.debug.dumpAllGeodesics().selectedTool`.
