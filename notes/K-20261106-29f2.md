Read from three 0.164.1 source and the repository at f9aa317; not exercised in a browser.

- Material.copy does not copy onBeforeCompile or customProgramCacheKey (they are prototype methods), so anything set on a source material in buildCellMesh is lost in cloneMaterial. Install patches on each clone.
- Material.copy copies userData through JSON, so plain numbers survive a clone. This is a cheap way to pass per-material shader data past cloneMaterial.
- WebGLRenderer.getProgram calls onBeforeCompile once per material even when the program is shared, so per-material uniforms work with a shared program.
- patchSinglePortalClipMaterial replaces customProgramCacheKey outright. Any earlier patch must be folded into the key or two differently patched materials with equal parameters share a program.
- Both the instanced material and the rootMesh material pass through cloneMaterial; the room the player stands in is drawn by rootMesh, so a patch on only one clone looks right through portals and wrong in the room, or the reverse.
- No code sets texture.anisotropy.
