Job 66, tested in tests/modules/vanishedAngles.test.ts.

- crossingsTick prunes the identity memory BEFORE update (it used to prune after), so a marker that vanished in this pass is still remembered for the ticks later in the same pass, and only then. getRememberedGeodesicIntersectionObject tells 'a crossing vanished' from 'an emitter was removed' in that one pass. Ids assigned are unchanged.
- A crossing id encodes where the marker was born, so a marker rebuilt after a load has another id if it moved. refreshProtractorAngleObject looks a missing centre up by cell, both sides' geodesics and the last centre point, within the 10 m continuity tolerance, and rebinds centerObjectId.
- Holding is never stored: the tick reads participants' attachments. vanishedSecondsLeft stands at 3 while held, so no timestamp of the end of an edit exists or is needed.
- The waiting set is a memo filled by the angles tick from the records; after a load the first refresh refills it.
- A hidden angle has no runtime: ProtractorAngleRuntime.syncFromObject rebuilds the whole group, and the countdown writes the record every tick.
- A side's endRole pins it to one half of its arc: a crossing that moves across the arc's midpoint makes the side unresolvable and the angle is deleted though the crossing lives (seen in a carry test; predates job 66).
- Free arcs are stored as two half segments, so a crossing at an arc's midpoint is at a segment end and the side's sign is forced: a test wanting 90 degrees got 270.
