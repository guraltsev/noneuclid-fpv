Observed: after the job 63 rename and module split, `npm run docs:generate`/`docs:check` failed on the `module names` check (scripts/docs/checks.mjs:128, scripts/docs/lib.mjs:686-698). The check requires every namespaced-looking string literal, and every kind, id, and command key a module contributes, to match `<moduleId>/<noun>`. Hygiene test H6 then failed on tool-lookup expectations in tests/render/toolHost.test.ts.

Concluded: new module contributions must follow the `<moduleId>/<noun>` naming, or docs:check and the hygiene tests fail. Check this rule before renaming kinds or tools in a module.
