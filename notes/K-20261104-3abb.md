Instrumented scratch copy of 869024b plus D2 (no isTied in the segment display state), flow+dependents scene, torus tied pair, one run to merge, 120 steps.

- Arc kind scans: 836 per run (6.97 per step). A cache invalidated by ANY arc write would recompute 120 times (one per step). With an anchor filter (recompute only when an arc's start or end anchor id changes, or on add/remove) it recomputes once. Arc updates: 238 keep the anchors, 1 changes them.
- So the plain cache plus a `relevant` filter is enough. `repair` is not needed for arc ends. 014 7.1 had hedged on this.
- Writes per run: 1918, 16.0 per step; 1197 of them are segment remove+add. A ring of 8192 holds about 512 steps.
- Remaining per-step scans after D2: arcs (476 from protractorTool refresh via endpoints, 238 from curve walking, 120 from flowVertex), getAll 3 per step from `measureLengthTool.ts` and `protractorTool.ts` `.getAll().filter`.
